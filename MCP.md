# MCP integration

Vajra provides a local stdio MCP server based on the official Python SDK 2.2.0. Local stdio was selected because the host launches a subprocess and there is no HTTP listener, remote auth endpoint, CORS, or network session to secure. The official SDK documents stdio as the local transport and Streamable HTTP for deployment; legacy SSE is not selected. [SDK transport docs](https://py.sdk.modelcontextprotocol.io/run/), [SDK release](https://github.com/modelcontextprotocol/python-sdk/releases/tag/v2.2.0).

Install from the public repository with `uv tool install --from git+https://github.com/mishraxram/vajra.git vajra-research`, then configure the MCP host with command `vajra` and args `["mcp"]`. Tools: `vajra_research(question, mode, sources_json)`, `vajra_replay(research_id)`, `vajra_audit(research_id)`, and `agent_reach_status()`. Research uses configured Agent Reach Exa search via mcporter plus DDGS, and can accept exact text returned by platform-specific Agent Reach tools in `sources_json`. Imported text is stored with tool/channel attribution, a content hash, and audited offsets; Vajra cannot independently attest that the external tool retrieved it. Follow with replay and audit before answering. There is no arbitrary shell, cookie, or general local-file tool. The research tool does bounded public search/fetch when called. MCP startup intentionally does not print the terminal banner because it would break the stdio protocol.

All tools return source text/metadata as untrusted research data. Stdout is reserved for MCP framing; ordinary logs go to stderr. The SDK is pinned to 2.2.0, the patched release observed after September/October 2026 advisories. Vajra does not use MCP's HTTP client or authorization features. Always review security advisories before upgrading. [SDK advisories](https://github.com/modelcontextprotocol/python-sdk/security/advisories).
